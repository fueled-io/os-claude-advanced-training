Three reasons

Audit trails

When a step changes data, write down what changed

  • What the step changed: rows removed, values corrected, records merged
  • Why: the rule it followed
  • How much: counts and totals before and after

How to write one: docs/audit-trails.md

Re-runs

Updated routines shouldn't unintentionally break historical data on re-run.

Every run writes a new file in outputs/history/. Nothing writes over an old one.

Hands-on · 30 minutes

Your workflow, in steps

  1. Ask for the plan first, from templates/workflow.template.md
  2. Give every step a done-check you can verify by looking
  3. Write the files: WORKFLOW.md and one file per step in steps/
  4. Label every file raw, derived, or historical
  5. Real data out of GitHub: in raw/ or in .gitignore
  6. Commit and push
