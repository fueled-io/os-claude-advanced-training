The five verbs

Everything you'll do with a repo

VerbCommandWhat it does
clonegh repo clone owner/repoDownload a copy of a repo, with its whole history, onto your computer
diffgit diffShow exactly what changed: lines removed (−) and added (+)
commitgit commit -m "note"Save a snapshot of your changes, with a note saying what and why
pushgit pushSend your commits up to GitHub so others can see them. A new branch's first push: git push -u origin alex-kim
pullgit pullBring down what others have pushed since you last looked

Exact commands and sources: docs/git-five-verbs.md

Memories vs. context vs. skills

What Claude knows, and for how long

ThingWhat it is
ContextEverything Claude can see right now, in this conversation. It has a size limit, and it's gone when the conversation ends.
MemoriesNotes Claude carries from one conversation to the next.
SkillsPackaged instructions Claude loads when a task calls for them.
CLAUDE.mdInstructions in a file in your repo. Claude Code reads it at the start of every session, and it changes only when someone commits a change.

Claude Code vs. Claude Chat/Cowork

Which one for which job

Claude Code

  • Work that lives in files, in a repo
  • Anything you or a teammate will run again

Claude Chat / Cowork

  • Questions, drafts, thinking out loud
  • One-off work you won't repeat

.gitignore for raw inputs

Some files never go to GitHub

Exports, PDFs, and customer data stay off GitHub. .gitignore is the list of files git refuses to commit. This repo's says:

.gitignore (excerpt) raw/* · *.csv · *.xlsx · *.pdf · *.export.json · exports/

It doesn't hide them from Claude. Anything Claude Code reads goes to Anthropic, so the AI acceptable use policy decides what goes in raw/.

This repo is public

Anything you push, anyone can read

  • Never: client or customer details, real business numbers, personal information, passwords or keys, internal links or screenshots
  • Stays on your computer: raw/, derived/, outputs/history/
  • Need an example? Make one up: "Client A", "$12,345"

Deleting it later doesn't unpublish it. Not sure? Don't commit it.

The full list: CONTRIBUTING.md

Why Artifacts and Projects aren't the source of truth

Deploy there. Keep it here.

  • No version history, no diff, no merge
  • Owner-only editing on skills
  • Instructions drift between accounts

Projects and skills are where you deploy a procedure. The repo is where it lives.

Hands-on · 30 minutes

Your first repo change

  1. Fork and download: gh repo fork fueled-io/os-claude-advanced-training --clone
  2. Go in, make your branch: cd os-claude-advanced-training · git switch -c alex-kim, with your own name
  3. Start Claude Code: claude
  4. Write a CLAUDE.md for one real workflow from templates/CLAUDE.template.md
  5. Have Claude make a change. Read the diff, then choose plain Yes, never "allow all edits"
  6. Commit, push, open a pull request. Nothing from raw/, nothing sensitive
